# 性能实验

实验设计见 [PLAN.md](PLAN.md)。目标是分别验证 Redis 前置过滤和 Kafka 异步缓冲的效果。

## 目录约定

| 位置 | 内容 | 版本管理 |
|---|---|---|
| `scripts/experiments/` | 执行入口、数据准备、采样工具与 k6 场景 | 入库 |
| `docs/experiments/<实验名>/<运行编号>/` | 报告、环境参数、指标和资源采样 | 入库 |
| `.local/experiments/` | 临时 Token、用户清单、执行锁 | 忽略 |

新实验分别使用 `redis-filtering/`、`kafka-buffering/` 作为报告目录。报告应记录输入条件、代码版本、实际配置、正确性核对、结果及适用范围；保留失败和不支持原假设的正式结果。大体积原始数据可单独归档，在报告中记录地址和校验值。不得提交密码、Token 或用户会话清单。

## 当前可执行入口

```bash
bash scripts/experiments/run.sh
```

当前入口迁移保留原有 A/B/C/D 场景，输出至 `docs/experiments/legacy-seckill/<时间戳>-<PID>/`，尚未实现 PLAN 中的新固定到达率 A/B、B/C 实验。因此不能把旧场景输出解读为新实验结果，也不能把 C 的 PENDING 受理数直接当成已完成订单数。

依赖本地后端已经启动、Docker Compose、Python 3、curl、OpenSSL 和 `flock`。仅在独占的本地实验环境运行；测量期间不得有其他发压端、手工购买或人工补偿操作。脚本会补齐演示数据，准备压测用户与 Redis 会话。压测源代码和临时会话目录分别只读挂载到 k6 容器。

每轮保存：

- `report.md`、`summary.md`：执行状态、场景汇总和口径限制。
- `manifest.json`：时间、代码提交、工作区状态、源码 SHA-256、输入参数及宿主机信息。工作区有未提交改动时，应一并提交对应源码才具备完整复现条件。
- `resources.json`、`images.txt`：公开的资源配额、网络及容器镜像信息，排除环境变量与含密码的启动命令。
- `k6-*.out`：k6 原始输出与 JSON 汇总；`abc.tsv`、`d.tsv`：表格输入。
- `resources-*.tsv`、`container-state.txt`：资源采样及容器 OOM 状态。

报告目录不被 `.gitignore` 忽略，运行后可直接审阅并提交。不要用缺少原始报告的预设性能数字替代实测。

## 数据重置与现场保留

脚本重置活动前检查 Kafka 三个分区的消费 lag 与未解决死信，目标活动包含非实验用户订单时拒绝覆盖库存。C 场景额外等待订单与积分流水数量一致，再进入后续阶段。这些是旧实验的清理前检查，不等同于 PLAN 中逐笔核对受理订单的完整正确性验证。

各场景显式输出 p50/p95/p99，缺失样本标为 NA；请求速率使用 k6 实际计数器 rate，网络失败计入 HTTP 错误。A/B/C 各自保存订单数量核对结果，D 场景不会重置 C 的订单现场。

正常完成和失败退出都会保留数据库现场及报告，不自动执行恢复。失败后的缓存开关也可能保留在当前实验状态。完成证据采集、核对在途请求与补偿任务均已结束后，可显式执行：

```bash
bash scripts/experiments/restore-demo.sh
```

该命令删除压测用户在活动 1001/2001/3001 的实验订单及关联流水，并把这三个活动设回演示库存和新的演示时间窗口。它不恢复执行前快照，也不修改其他六个演示活动；压测用户和会话继续保留。该命令同样拒绝在 Kafka 未排空或存在未解决死信时清理。

下一轮执行仍会重置目标活动，因此需先归档上一轮结果。PLAN 中的流量构成、端到端完成时间和逐笔结果核对留在后续实验逻辑重构中实现。
